# BPEByte root_greedy — Critical Review Status (2026-06-22)

Triage of the 5-parallel-agent adversarial review of **BPEByte root_greedy** (causal boundary
generation + evaluation leakage/error). Each item: status, evidence (`file:line`), severity.

## ✅ Closed

- **C — loglikelihood "leak" for root_greedy** — RETRACTED. Root placement (`off=0`, mark on the
  dead-end byte `e`) makes the full-string `cumsum` segmentation provably **causal**. Probe
  (`lingua/probe_root_causal.py`) on the real llama3 trie: **root 0/442 byte leak (0.0%)** vs
  before_root 118/442 (26.7%), across ASCII/UTF-8/Korean/code/whitespace. The earlier "83% leak"
  was a **before_root** artifact (streaming parser at OFFSET=1). Downstream MCQ loglikelihood never
  enters the rollback loop (teacher-forced prefill) so it cannot roll back either.

- **BOS train/eval mismatch (Agent 1, Bug F)** — FIXED. Training ran the trie on `text.encode()`
  only (BOS as a separate slot); eval fed `[BOS=256, …]` so BOS dead-ended the trie → a spurious
  patch boundary on the **first content byte (pos 1)**. Fix in `regex_cutting._online_levels_mask_bytes`:
  peel leading special tokens (id≥256), mark each as its own boundary, segment the real bytes, shift —
  eval mask now **bit-identical to training** (verified). Full 5-bench re-run @180k = **score-neutral**:
  | bench | metric | baseline | with-fix | Δpt |
  |---|---|---|---|---|
  | hellaswag | acc_norm | 0.6301 | 0.6272 | −0.29 |
  | arc_easy | acc_norm | 0.6587 | 0.6566 | −0.21 |
  | boolq | acc | 0.6021 | 0.6012 | −0.09 |
  | piqa | acc_norm | 0.7339 | 0.7372 | +0.33 |
  | winogrande | acc | 0.5927 | 0.5967 | +0.39 |
  All within stderr, mixed signs. Existing published numbers stand. (Upstream AU-Net never had this:
  BOS-into-trie is unique to the BPEByte online path; offline AU-Net + llama eval handle BOS
  consistently via `p_len=encode(prompt,add_bos=False)` + `ll[p_len:]`.)

- **Llama `p_len` junction (Agent 3 top open-Q)** — EXPLAINED, by design. `apps/main/eval.py:218`
  uses `encode(prompt)` alone; for subword this misaligns at a mid-token junction, but that IS the
  Prompt-Boundary-Problem signal, acknowledged at `apps/main/eval.py:344-345`. Byte model is exact
  (UTF-8 concat). Not a bug.

## ✅ Closed (2026-06-22 batch)

### A.1 — greedy trailing-token boundary — FIXED + measured score-neutral
`byte_trie.py:greedy_tokenize_boundaries` now appends the final boundary in the `for…else` branch
(mirrors bt `:59-62`). Verified: `'the'`→`[3]`, `'The quick'`→`[3,9]` (was `[]`,`[3]`). **Empirical
effect on current root_greedy@180k (vs BOS-fix-only): hellaswag −0.02, arc_easy +0.00, boolq +0.06,
piqa −0.05 pt — score-neutral** (the trailing patch only affects predicting the byte *after* the last
byte, which isn't scored). So A.1 does NOT affect current performance; safe to keep, makes greedy
consistent with bt. Tests in `apps/aunet/test_greedy_root.py`.

### B.2 — test coverage — DONE
New `apps/aunet/test_greedy_root.py` (6 tests, CPU, no GPU): greedy trailing-close, forward-only
prefix-consistency, special-token (BOS) dead-end, **BOS train/eval alignment**
(`online_levels_mask(text)==get_levels_mask([BOS]+bytes)`), root-marks-dead-end-byte, and **streaming
greedy no-retraction within window** (generation-time causality). All pass; existing 6 still green.

### B.3 — streaming-generation window-edge artifact — MEASURED + FIXED
`probe_streaming_leak.py` on the actual `ByteTrieIncrementalParser` (greedy+root) found the streaming
parser rewrote committed boundaries at the sliding-window leading edge for >4096 B input — and this
was NOT benign: it actually CORRUPTED the long-sequence finalize() (root gave 910 boundaries vs the
correct ~2000 on a 9000 B doc). Root cause: `_recompute` set `start = len(buf) - window`, a fixed
offset that lands MID-token; greedy restarting mid-token disagrees near the edge. **Fix** (`byte_trie.py:
_recompute`): anchor `start` to the last committed token-start ≤ `raw_start` (greedy is memoryless at
boundaries) and preserve the committed mark at the anchor. Result: **0 retractions, and streaming
finalize() == batch ground-truth on 9000 B / multibyte for both placements.** Regression test
`test_streaming_finalize_matches_batch_across_window`. (Latency note: root is 0 *information*-latency;
the `commit_margin=1` is a conservative parser exposure delay only.)

### B.4 — backstop off-policy accept — INSTRUMENTED + run
`generate_bt.py` now counts/warns on every backstop firing (`BACKSTOP_FIRINGS`, both decode loops).
CUTE generation (18 subtasks, real generation) on root_greedy@180k: **0 firings across the entire run**
(confirmed; rollbacks did occur but never hit `PER_POS_CAP`). Conclusion: the off-policy-accept path is
dormant for short generation; only long code-gen (window-crossing, per B.3) could trigger it.
Generation-only, never touches scored metrics.

### C.5 — few-shot truncation asymmetry — QUANTIFIED + FAIR RE-EVAL RUN (c5_fewshot_truncation.md)
Reproduced: BoolQ byte-model truncation 0%(0-2shot) → 0.03%(5shot) → **15.9%(10shot)** vs Llama 0%.
Cause: shared `p[-max_prompt_len:]` truncation, budget binds on 8192 BYTES (byte) vs 4096 TOKENS
(Llama). **Ran the fair comparison at clean shot counts** (root_greedy 1.3B@180k vs Llama 1.8B@60k):

| BoolQ acc | byte | Llama | gap |
|---|---|---|---|
| 0-shot (clean) | 0.5988 | 0.6333 | Llama +3.5 |
| 5-shot (clean) | 0.6550 | 0.6541 | **byte +0.1 (tied)** |

At the fair 5-shot point byte ≈ Llama (within stderr ~0.008); the byte model gains MORE from few-shot
(+5.6 vs +2.1 pt). **Use 0- or 5-shot for byte-vs-Llama BoolQ; never 10-shot** (byte truncates 15.9%).

### D.9 — BPB confidence interval — bounded (bpb_ci_1.3B.md)
Reproduced published BPB exactly (root_greedy 0.8603, AU-Net2 0.8657, Llama 0.8383). Moving-block
bootstrap on the steady-state tail → **±0.001 within-run band**. Verdict: **root_greedy vs AU-Net2
(Δ0.0054) is NOT distinguishable** (≈ the ±0.005 seed-floor); **both vs Llama (Δ≈0.022-0.027) IS
robust**. Caveat: this is within-run noise, NOT cross-seed CI (needs ≥3 reruns; val-bootstrap
infeasible — eval.py averages nll_per_byte before saving).

### D.11 — eval JSON provenance — DONE
`apps/aunet/eval.py` now writes `results["eval_meta"]` + `<dump_dir>/eval_meta.json` recording
ckpt_dir, consolidate_path, bpe_online_mode/placement/context_prefix/committed_view, and model
dim/layers. Add-only (ablation_results.py unaffected).

## Follow-up: 5-shot fair comparison (2026-06-22)

Truncation-free (0% for all three, verified) MC comparison of the 1.3B-scale models — byte
**root_greedy**, **AU-Net2** (whitespace-patch byte), and **Llama 1.8B** — at 0-shot vs 5-shot,
acc_norm, full sets, fixed root_greedy code (BOS/A.1/window). Single run, no seeds (per-bench gaps
~1-2 stderr; read the consistent direction, not any single cell).

**0-shot**
| bench | byte | aunet2 | llama |
|---|---|---|---|
| hellaswag | 0.6301 | 0.6265 | 0.6224 |
| arc_easy | 0.6587 | 0.6566 | 0.6545 |
| boolq | 0.6021 | 0.6113 | 0.6346 |
| piqa | 0.7339 | 0.7421 | 0.7530 |
| winogrande | 0.5927 | 0.6148 | 0.6156 |
| **mean** | 0.6435 | 0.6503 | **0.6560** |

**5-shot**
| bench | byte | aunet2 | llama |
|---|---|---|---|
| hellaswag | **0.6372** | 0.6371 | 0.6289 |
| arc_easy | 0.7189 | **0.7239** | 0.7029 |
| boolq | 0.6550 | 0.5905 ⚠ | **0.6557** |
| piqa | 0.7437 | 0.7410 | **0.7557** |
| winogrande | **0.6409** | 0.6361 | 0.6259 |
| **mean** | **0.6792** | 0.6657 | 0.6738 |

**Finding:** at 0-shot the order is Llama > AU-Net2 > byte root_greedy (subword leads). At 5-shot byte
root_greedy **overtakes both** (0.6792 > Llama 0.6738 > AU-Net2 0.6657) — it has the strongest few-shot
scaling and stays stable everywhere, whereas **AU-Net2's BoolQ collapses to 0.5905 (~chance)**, dragging
its 5-shot mean below Llama. Suggests BPE-derived (root_greedy) patching is more few-shot-robust than
whitespace patching. **Caveats:** single run / no CI; byte 1.3B vs Llama 1.8B (param-mismatched);
AU-Net2's BoolQ 0.5905 is suspiciously low and needs a seed-repeat to rule out a one-off. **Next:**
3-seed re-run of the 5-shot sweep with mean ± CI before any citable "byte LM matches/beats subword
in-context" claim.
