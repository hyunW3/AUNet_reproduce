# CharBench · Strawberry · CUTE-MC — 1.3B trio + BLT / H-Net (2026-10-07)

코드: `scripts/probes/charbench/` (build_items.py, run_charbench_lingua.sh, run_charbench_ext.py, summarize.py,
summarize_cute_mc.py). 문항/YAML·원시 결과는 공용 체크아웃 `reports/charbench/{items,runs,runs_cute}/` (gitignore 대상 아님,
크기 때문에 미커밋). 상세 표: `summary_all.md` (CharBench/Strawberry 태스크별·단어길이별), `summary_cute_mc.md`.

## 설정
- 모델: Llama 1.3B@60k, AU-Net2@180k, BPEByte-rg@180k (md5 3fbc9bbf…), BLT-1B 공식 bytelatent xformers bs1
  (θ=1.335 / 1.609), H-Net 1-stage XL (info103, torch 2.6 + flash-attn 2.7.4; bf16 decode가 run 간 ~4% 비결정적).
- CharBench (HF omriuz/CharBench): 4태스크 × 1000 (단어 길이 4–10 균등), 논문 지시문 + 5-shot.
  gen = 첫 정수 exact match; cloze = `Answer:` 뒤 " 0"…" len(word)" 각각의 loglik 최대 (보기 글자·보기 나열 없음).
- Strawberry (cosmaadrian/strawberry-problem 테스트 20태스크, 위키 문장 ≤64자) × 200, 5-shot `Task/Input/Output`.
  cloze 보기 = 정답 + 같은 태스크 다른 파라미터 결과 + 입력 그대로 + 인접 문자 교환 (찍기 25).
- CUTE MC (leukas/cute 14 × 1000): 원 프롬프트 + ` Answer:`, 보기는 각 split 데모의 따옴표 형식 그대로.
  contains: Yes/No, orth/sem: 질문의 두 단어, 편집 10종: 정답 + 다른 인자 편집 + 입력 그대로 + 인접 교환/한 글자 삭제.
  재구현 편집 = CUTE 정답 100% (char) / 99.2–99.3% (word).
- BLT/H-Net 생성은 stop byte에서 조기 종료 (BLT limit-2 생성 48/48 출력 동일).

## 결론
1. CharBench / Strawberry: 1.3B base 규모에서 전 모델이 랜덤·최빈답 수준 → 토크나이저 효과 측정 불가.
2. CUTE MC는 변별력 있음: **spell** 에서 바이트 모델 (AU-Net2 99.5, BPEByte 95.0, BLT ≈100) ≫ Llama 33.9 / H-Net 18.4
   (둘은 띄어 쓰지 않은 원 단어를 고름). 생성형 CUTE (20.1 / 88.4 / 22.1)보다 차이가 선명하고,
   BPEByte의 생성형 실패 (22.1)가 표현이 아니라 디코딩 문제임을 보여 줌.
3. Sequence 편집은 BLT만 찍기 이상 (47–55); trio·H-Net은 복사 편향으로 찍기 이하.
