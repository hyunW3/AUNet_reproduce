0. One-paragraph pitch (the claim we can defend today)

Byte-level LMs remove the tokenizer's brittleness (prompt-boundary sensitivity, typo fragility, no character access) but pay for it in sequence length and, empirically, in clean-task accuracy. Dynamic patching (BLT, SpaceByte, H-Net) recovers efficiency, but the patcher is either a separate learned model (BLT entropy model, H-Net router) or a coarse heuristic (whitespace). BPEByte asks a narrower question: what if we keep the proven byte-level information of a BPE tokenizer — its merge statistics — but use them only to place pooling boundaries, fully causally, while the model still reads raw bytes? The boundaries reproduce subword fertility exactly, yet every boundary is a deterministic function of past bytes only (leak-free, verified ΔBPC = 0), so train, eval, and streaming generation are bit-identical. Across 100M / 760M / 1.3B matched-compute runs, BPEByte (i) matches or beats the AU-Net word-patch baseline at every scale, (ii) is completely immune to the Prompt-Boundary Problem that costs the subword baseline up to −8.9 MCQ points and +1.18 BPC, (iii) is more typo- and noise-robust, and (iv) overtakes the 1.8B subword baseline on 5-shot core reasoning (67.9 vs 67.4) — closing the byte↔subword quality gap as scale grows.

1. Introduction

The tokenizer is a liability

  • Prompt-Boundary Problem (PBP). A trailing space re-tokenizes the continuation; the subword baseline's BPC jumps +1.18 (English) and MCQ accuracy drops −8.9 pts on average. Byte models are invariant by construction.
  • Typo / noise fragility. One edit reshatters the token stream. On noisy ARC-Easy the subword baseline drops −10.7 pts vs BPEByte's −6.6.
  • No character access. Subword IDs are opaque; spelling, character counting, and orthographic tasks are bottlenecked (CUTE).
  • Format brittleness. Letter-MMLU pins all models at the chance floor (~24–26); scoring the answer text instead lifts every model by +9–11 pts — a tokenization-of-the-label artifact, not a knowledge gap.

But naïve byte models lose, and dynamic patchers add a moving part

Pure byte sequences are ~4.5× longer (DCLM: 4.54 bytes/llama-token), so a global transformer over raw bytes is wasteful. The field's answer is patching: pool bytes into variable-length units and run the deep trunk over the pooled stream. The open question is how to choose the boundaries. BLT learns a separate entropy model; H-Net learns an end-to-end router; SpaceByte uses whitespace. Each adds either a second trained network or a heuristic that is poorly matched to morphology.

Our position

BPE merges already encode a strong, cheap, data-driven segmentation that the field spent a decade tuning. Reuse those statistics as a boundary oracle — not as a vocabulary. The model never sees a token ID; it reads bytes and pools them at BPE-derived cut points produced by a streaming greedy longest-match over a merge trie. This is the missing "free" baseline between whitespace patching and a learned patcher — and, made causal, it is the first BPE-guided byte model with exact train/inference parity.

Contributions

  1. A causal, leak-free, online BPE-trie patching scheme (root_greedy) with verified zero boundary leakage (ΔBPC = 0.000) and identical batch / streaming masks.
  2. A matched-compute, 3-scale study (100M / 760M / 1.3B) isolating the boundary mechanism against AU-Net word patches and a subword Llama baseline.
  3. A boundary-scheme ablation (committed-view vs. greedy vs. prefix-free vs. prefix-vocab; root vs. before-root placement) quantifying exactly what the leak buys and where placement matters.
  4. A robustness suite (PBP cut-invariance, HellaSwag-Noise, typo-downstream, CUTE) where byte patching wins, plus the MMLU letter-vs-text reframing showing the format gap dwarfs every model gap.

2. Related work

BLT — Byte Latent Transformer

Entropy-based dynamic patching.

A small byte-LM scores next-byte surprise; high-entropy positions open new patches. Local encoder/decoder + latent transformer over patches.

Contrast: BLT needs a separately trained entropy model and a calibrated threshold per domain. BPEByte's oracle is the existing BPE trie — no extra network, no θ tuning. We include a BLT-style entropy variant (v8) as a head-to-head.

ByteFlow Net — coding-rate chunking

Deng et al. (Rice / Amazon).

Boundaries chosen inside the model from learned encoder hidden states by promoting positions of maximal marginal coding-rate ΔR. Global Top-K selection.

Contrast: Top-K is non-causal (membership depends on future scores) and the authors' "rolling top-k" still leaks at training. BPEByte is a deterministic function of past bytes — strict train==gen parity, no leak.

H-Net — hierarchical dynamic chunking

Learned, end-to-end boundaries.

A differentiable router learns where to chunk, trained jointly with the LM; stacks hierarchies, fully tokenizer-free.

Contrast: maximal flexibility but a new learned component with its own optimization difficulty and load-balancing. BPEByte trades learned boundaries for a fixed, interpretable, zero-extra-parameter oracle — a strong, cheap reference point H-Net should be measured against.

SpaceByte

Whitespace-delimited patches.

Inserts global transformer blocks at space boundaries; simple and tokenizer-free but coarse and language-dependent (fails on no-space scripts / code).

Contrast: our AU-Net word-patch baseline is the SpaceByte family. BPEByte's BPE boundaries are finer and morphology-aware, and we show they beat whitespace at all three scales.

3. Method

3.1 Backbone (unchanged AU-Net hierarchy)

bytes x_1:T  →  Local Encoder  →  h_1:T
            →  Downsample (pool at boundaries)  →  z_1:K   (K ≪ T)
            →  Global Trunk (deep, full causal attn over K patches)  →  g_1:K
            →  Upsample (broadcast + residual from h)  →  s_1:T
            →  Local Decoder  →  p(x_{t+1} | x_1:t)

The only thing that varies across our models is how the K pooling boundaries are produced. Everything else (params, data, optimizer, seq len) is held fixed, so the comparison isolates the boundary mechanism.

3.2 The root_greedy boundary scheme

Given the byte stream, we run a streaming greedy longest-match over the BPE merge trie: at position pos, walk the trie as far as the upcoming bytes allow, emit a patch boundary at the end of the longest matched merge, advance, repeat. "root placement" puts the boundary marker at the patch's first byte (the trie root), so the boundary token is determined the instant the patch opens.

The causality argument (the technical core)

A boundary is leak-free iff membership of byte t in its patch depends only on bytes ≤ t. The danger case is "before_root" placement, where the cut can peek at the breaking byte (the byte that ends the longest match) — that byte is in the future relative to the bytes it terminates. We show this leak is small but real: it inflates HellaSwag specifically by ~+0.36 (v6 vs v6-root) and nets ~0 on average. root_greedy with root placement removes it entirely: ΔBPC = 0.000 between an aligned cut and a mid-token committed cut, and the batch-training mask equals the streaming-generation mask byte-for-byte (no commitment lag, no rollback).

Why this matters operationally

  • Train == eval == generate. No teacher-forcing-only shortcut, unlike global Top-K (ByteFlow) or BLT's full-sequence entropy at train time.
  • No second network, no threshold. The oracle is the frozen BPE trie shipped with any subword tokenizer.
  • Fertility-matched to subword. By construction BPEByte fragments a word exactly as the subword baseline does — so any quality difference is attributable to byte access, not to a different segmentation granularity (clean covariate control; see idea_oov_eval.md).

3.3 Implementation notes

  • Special tokens (BOS = 256) overflow uint8 and break naïve trie walks → cast to int64; commit unknown bytes as 1-byte patches (longest_match = max(1, i−pos)) to avoid the greedy infinite loop.
  • Streaming decode never rolls back (loglikelihood path is exact); only very long autoregressive code-gen hits an O(n²) re-prefill cost — a known limitation to fix, not a correctness bug.

5. Analysis & ablations

5.1 Boundary-scheme ablation (100M, ratio-40, 84B bytes)

Same architecture; only the boundary scheme differs. This is the "what exactly does the boundary choice buy" experiment.

Findings

  • Leak-free byte ≥ word baseline. Every leak-free scheme (v6-root, v4, v7) ties or beats whitespace patching — no penalty for raw bytes with a causal boundary.
  • The boundary leak buys ~+0.36 HellaSwag but ~0 on average (v6 vs v6-root) — it inflates one task, not capability. Removing it is "free."
  • committed-view (v1) is the weakest (−1.5 to −2 avg) — the delayed 3rd-view mask underperforms greedy/trie schemes and costs 2× wall-clock.
  • Subword-warm-start does not help at adequate training budget (consistent with an undertraining-regime effect: warm-start helps only when more undertrained).

5.2 New-code vs old-code (760M)

The current causal implementation nets +0.0092 mean across downstream vs the old code point, mostly redistribution (BoolQ ↑0.06, MMLU/ARC-C ↓) — both versions verified leak-free. Useful as an honesty/ablation panel, not a headline.

5.3 Efficiency (to be measured — see Appendix B)

Wall-clock at 100M/4×A100: standard byte ~4.1 s/step vs Llama ~2.1 s/step; committed-view ~8.1 s/step. The paper needs a proper bytes/patch, sequence-compression, and inference-throughput panel — currently the weakest-covered axis.

6. Conclusion

  • BPE merge statistics are a free, causal, leak-free boundary oracle for byte-level LMs — no second network (BLT), no learned router (H-Net), no non-causal Top-K (ByteFlow).
  • At matched compute, BPEByte matches/beats whitespace patching at every scale and overtakes the subword baseline on 5-shot reasoning at 1.3B, while being immune to the Prompt-Boundary Problem and more robust to noise and typos.
  • The byte↔subword quality gap (clean MC, BPB) narrows with scale but is not yet closed on the core LM metric — the honest framing is "robustness now, parity approaching."
  • Future: fix long-gen O(n²) re-prefill; multilingual / code; head-to-head vs BLT entropy patching (v8) and H-Net.

What reviewers will praise

  • Clean causal-leak analysis. The ΔBPC = 0 vs +1.18 PBP result is mechanistic, quantified, and reproducible — a genuinely nice contribution. Reviewers love a sharp, falsifiable claim.
  • Matched-compute, multi-scale discipline. Three scales with held-fixed everything-but-boundary is more rigorous than most byte-model papers.
  • The "free oracle" angle. "Reuse BPE statistics as boundaries, not vocabulary" is a crisp, memorable framing that BLT/H-Net don't occupy.
  • MMLU letter-vs-text is a quotable, broadly-useful observation.

What reviewers will attack (the rejection risks)

  1. "It loses on the core metric." BPB is worse than subword at every scale (0.9256 vs 0.9234 at 760M); clean MC trails until 1.3B few-shot. A skeptic reads this as "byte models still don't win where it counts." The robustness wins must be framed as the contribution, not as compensation.
  2. "Single seed, no CIs." The headline 1.3B result (67.9 vs 67.4) is a 0.5-pt gap with no error bars — within plausible seed noise. This is the single most likely reason for rejection at ICLR. Must be fixed.
  3. "Novelty is incremental vs BLT/H-Net." The backbone is AU-Net; the idea is "a different boundary function." Reviewers may file it as a boundary-ablation paper unless the causal-parity property and the BPE-statistics framing are elevated to a real conceptual contribution with a head-to-head vs BLT/H-Net under matched compute.
  4. "No efficiency numbers." The entire premise of patching is efficiency, yet there's no throughput / FLOPs / sequence-compression panel and the byte model is slower per step. A byte-patching paper without an efficiency frontier is half a paper.
  5. "Boundary-study, not a method." (Internal audit already flagged this.) The paper reads as exploratory unless it is re-framed around a pre-registered claim with the right controls.
  6. "Generation is broken." The long-gen O(n²) re-prefill / hang must be at least characterized; reviewers will ask.

Appendix B — How to make it accept-worthy

Ordered by (impact × feasibility). The first three convert "borderline" → "main-track competitive."

★★★ Tier 1 — do these or don't submit to a main track

B1. Seeds + confidence intervals on the headline

Run ≥3 seeds (or bootstrap CIs over eval items) for the 1.3B core-reasoning and the 100M ablation. The 67.9-vs-67.4 claim is indefensible without them. Cheap relative to the training already done — re-eval is minutes; if seeds are unaffordable, at minimum report per-item bootstrap CIs and frame gaps honestly as ties where ≤1 se. cost: low

B2. An efficiency frontier (the missing half of the paper)

Plot quality vs. inference cost (and vs. training FLOPs): bytes/patch achieved, sequence-length compression, tokens/sec at generation, KV-cache size, wall-clock per generated character. Show BPEByte sits on or near the subword Pareto frontier while subword is off it on robustness. Without this, "patching" has no payoff axis. cost: medium

B3. Head-to-head vs BLT entropy patching under matched compute (v8)

The v8 entropy study is already running. Land it: BPEByte vs BLT-style entropy boundaries vs Meta's blt-entropy ceiling, same backbone/data/budget. "Our free BPE oracle matches a separately-trained entropy model" is the result that converts incremental-novelty into a real comparison. cost: medium (in progress)

★★ Tier 2 — turns a Findings paper into a main-track contender

B4. Multilingual / morphologically-rich + code  full design → Appendix C.1

BPE fertility is worst exactly where byte access should help most: agglutinative languages (Finnish/Turkish), no-space scripts (Chinese/Thai), and code. A clean win on FLORES-style multilingual BPC or a non-English reasoning benchmark would be the strongest new evidence and directly answers "why not just use subword." Crucially, AU-Net word-patch is the baseline that makes this experiment a proof, not a demo: whitespace patching collapses on no-space scripts and code, so BPEByte beating AU-Net there isolates "BPE boundaries" as the cause, independent of byte access. The single best ACL/EMNLP move. cost: medium-high

B5. The OOV / nonce copy-spell motivation experiment

Already designed (idea_oov_eval.md). Because BPEByte is fertility-matched to subword, a real-vs-nonce copy/spell task isolates character access as the sole causal variable. A win here is the cleanest possible motivation figure: "same segmentation, byte access alone buys X." Put it in the intro as Figure 1. cost: low

B6. Scaling law / compute-optimal frontier  PROMOTED to required  full design → Appendix C.2

Fit the byte↔subword gap vs scale across all points and extrapolate the crossover. "The gap closes at compute C*" is a far stronger claim than three disconnected tables, and reviewers increasingly expect a scaling argument from any "X is competitive" paper. Most of the grid already exists (ratio-5/10/20/40 at 100M + 760M + 1.3B), so this is largely a fitting exercise on data already collected, plus a few fill-in points. cost: low–medium (mostly fitting existing runs)

★ Tier 3 — polish & defense-hardening

  • Fix / characterize generation. Bound or fix the O(n²) long-gen re-prefill; report streaming-gen parity explicitly (it's a strength — sell it).
  • Pre-register the claim. Re-write Method around one falsifiable thesis ("causal BPE boundaries match learned patchers at lower cost and zero leak") so it reads as a method, not a sweep. Move v1–v8 to a clearly-labelled ablation.
  • Add the missing controls the internal audit flagged (e.g., a fertility-matched random-boundary control to prove BPE structure — not just patch count — is what helps).
  • Decompose CUTE. BPEByte trails AU-Net word on CUTE avg (20.6 vs 23.9) — explain why (word patches help spell specifically) so it's not read as a loss.
  • Tighten BPB framing. Report BPB and downstream together; argue (with the PBP/robustness data) that BPB under-credits byte models because it ignores boundary brittleness.

The one-sentence strategy

Reframe from "byte models can be competitive" (defensive, loses on BPB) to "BPE statistics are a free, causal, leak-free patcher that buys provable boundary-robustness at near-zero quality cost — and the cost vanishes with scale." Then back it with seeds (B1), an efficiency frontier (B2), and a BLT head-to-head (B3). That package is an ICLR/ACL main-track submission.

Appendix C.1 — Experiment design: multilingual & code (B4)

Thesis

BPEByte's advantage over baselines grows with BPE fertility and is largest exactly where whitespace patching breaks. Two separable wins, two different baselines beaten:

Llama (subword)no (opaque IDs)yes (BPE)char tasks, high-fertility langs, PBP

This 2×2 is the experiment's logic: BPEByte − Llama isolates the value of byte/character access (both share BPE-style fertility); BPEByte − AU-Net isolates the value of BPE boundaries over whitespace (both share byte access). A win over both on the same multilingual/code suite is a clean causal claim that neither byte access alone nor good boundaries alone explains the result. Without AU-Net in the grid, a reviewer can say "it's just a byte model" — AU-Net is the rebuttal.

C1.2 Models & training

  • 4 families, matched compute: Llama subword · AU-Net word-patch · BPEByte root_greedy · (stretch) BLT-style entropy v8. Same backbone/params/optimizer; Llama iso-byte.
  • Scale: one tractable scale for the multilingual study — recommend 300M or 760M (760M already exists for English; mirror the recipe). Train on a multilingual+code mix, not English-only DCLM.
  • Data: CulturaX or mC4 subset spanning ~15–25 languages chosen to span the morphology grid below, mixed with The Stack v2 (code). ~50/50 NL/code or 70/30. Hold out a per-language + per-code-language test split for BPB.
  • Tokenizer note (must report): BPEByte and Llama share the same BPE tokenizer, so cross-language fertility differences are identical for both → fertility is a clean covariate, not a confound. Run once with the (English-centric) llama3 tokenizer and once with a multilingual tokenizer to show the byte advantage is largest precisely when the tokenizer is a poor fit (the realistic deployment case).

Appendix C.2 — Experiment design: scaling law / compute-optimal frontier

Thesis

The byte↔subword BPB gap shrinks predictably with compute and crosses below subword at a finite, extrapolable compute C*. This converts the three disconnected scale tables into one quantitative law — the difference between "byte can be competitive" (weak) and "byte overtakes subword beyond C*, and here is C*" (strong).

C2.1 Why BPB is the right axis (not per-token loss)

Per-token loss is not comparable across tokenizers (a subword token ≈ 4.5 bytes). BPB (bits-per-byte) normalizes that away — it is the only loss metric on which byte and subword models can share a y-axis. The 760M table already does this conversion (Llama 2.9044 nats/token ÷ ln2 ÷ 4.5376 B/tok = 0.9234 BPB). Every point in the scaling fit must be BPB. Include all 4 families (Llama, AU-Net word, BPEByte, BLT-v8) so the law shows the full ordering and each family's exponent.

C2.3 Two complementary fits

(a) Chinchilla-form loss surface

L_BPB(N, D) = E + A / N^α + B / D^β        # D = bytes seen, N = params

Fit {E, A, B, α, β} per family by L-BFGS on log-Huber loss (Chinchilla Approach 3).
Report per family:
  • E   — irreducible BPB  (does byte have a lower floor?)
  • β   — data-scaling exponent  (do byte models convert data faster?)
  • the compute-optimal ratio  D*/N  (byte models see more bytes → expect different optimum)

(b) Compute (FLOPs) frontier & the crossover C*

For each family, plot min-BPB vs training FLOPs C  (the compute-optimal envelope).
Fit   L_BPB(C) = L_inf + (C / C0)^(-a).
Crossover:  solve  L_BPEByte(C*) = L_Llama(C*)   →   report C* (and whether C* is
            below, within, or beyond the 1.3B compute already spent).

FLOPs accounting must be fair (the reviewer will check this)

Byte models run a longer encoder/decoder (over T bytes) but a shorter trunk (over K ≈ T/4.5 patches); subword runs everything over T/4.5 tokens. Count FLOPs as C ≈ 6N_enc·T + 6N_trunk·K + 6N_dec·T vs subword 6N·(T/4.5) — not by step count. The 100M ablation's "iso-byte Llama runs more steps" convention is the right instinct; formalize it into an explicit per-family FLOPs ledger and report the frontier on FLOPs, not steps. Also report a wall-clock / throughput frontier (byte ~4.1 vs Llama ~2.1 s/step) so the efficiency cost is visible alongside the quality crossover.
